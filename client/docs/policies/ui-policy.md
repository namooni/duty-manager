# UI 정책

상태: 목표 UI 정책. 현재 화면에 모두 구현된 것은 아니다.
업무 의미·휴일·중복 판단은 [공통 정책](../../../docs/policies/duty-policy.md)이 기준이다.

## 현재 구현: 실행 일정과 담당 교대 분리

- 생성은 ‘실시일·교대 규칙 설정 → 참가자 전체 한 바퀴 순번 확인 → 시작’이다. 배정 최종일·6주 확정·추가 수동 확정은 신규 생성 흐름에서 제거했다.
- 실행 일정은 WORKDAYS / WEEKLY / DAILY_INTERVAL / MONTHLY_DAY / MONTHLY_NTH_WEEKDAY / EXPLICIT_DATES를 지원한다. 회사 근무일 기본은 월~금이며 회사 휴일을 등록할 수 있다. 근무 요일 자체의 회사별 편집은 아직 없다.
- 담당 교대는 CALENDAR(일·주·월의 달력 기간)와 OCCURRENCE(실행 1회마다)를 구분한다. 개별 개최일은 OCCURRENCE만 허용한다.
- 정례회 회의록은 날짜 한 건으로 표시한다. 날짜 미정인 차기 회차는 ‘開催日未定’과 다음 담당자를 보여주며, 개최일을 나중에 등록하거나 순서를 유지하면서 변경할 수 있다. 날짜 변경은 회차 번호와 담당자를 유지한다.
- 생성 미리보기는 참가자 전체가 최소 한 번 포함될 만큼 보여준다. 5명·1명씩이면 최소 5회이며, 등록한 개최일이나 표시 회차가 더 많으면 그 수만큼 모두 보여준다. 실제 개최일이 부족한 나머지 회차는 미정으로 보여주는 순번 예시이며, 차기 미정 회차를 제외한 빈 개최회차를 모두 저장하지는 않는다.
- EMPLOYEE_NUMBER / SHUFFLED_ROUND는 활성 직원 전체를 기본 선택하며 제외할 사람만 해제한다. CUSTOM은 선택 순서로 배정한다. 전체 선택·해제와 최대 200명을 지원한다.
- 새 당번은 운영 종료일(선택)과 담당 배정 범위(필수)를 분리한다. 지정 범위를 미리보고 저장하며 조회는 담당을 생성하지 않는다. 상세의 「担当予定を追加」에서 다음 범위를 검토·추가한다. [배정 범위 정책](../../../docs/policies/allocation-window-policy.md)을 따른다.
- 스케줄은 ‘実施日・当番・担当者・担当の交代’를 구분한다. 기간 교대만 보조 정보로 담당 기간을 표시한다. 발생 없는 휴일은 ‘実施なし（会社休業日）’로 표시하며 자동 이동하지 않는다.
- 회사 휴일 지정/해제는 교대 기준을 밀지 않는다. 이미 회차가 예약된 휴일은 실행 없음으로 남겨 기존 회차 번호와 다음 순서를 보존한다.
- 저장된 담당을 바꾸면 사유와 이력을 남기며 이후 순번은 바꾸지 않는다. 달력 담당 기간의 대타는 해당 기간 전체에 적용된다. 과거 기간은 변경할 수 없다.
- 입력으로 돌아가기는 입력을 보존한다. 취소·닫기·ESC는 생성 전 저장하지 않는다. 처리 중 중복 요청·닫기를 막는다.
- 이전 형식의 업무는 실행일을 추측해 자동 변환하지 않는다. 기존 담당 기간·변경 이력은 별도 영역에 유지한다. 신규 방식이 필요하면 실행일과 규칙을 명시해 새로 등록한다.
- 영속 초안, 실시일 규칙 버전 편집, 멱등 키, preview 만료, 과거 발생 건별 담당 snapshot 및 FORBID는 여전히 목표 설계다. 아래 수동 확정/checkpoint 관련 정책은 기존 호환 API 또는 향후 관리자 일괄 조정에 해당하며 신규 생성의 필수 단계가 아니다.

## 1. 공통 표현

- 서비스 언어는 일본어, 업무 시간대는 Asia/Tokyo다. 브라우저 시간대로 날짜가 바뀌지 않게 한다.
- 날짜 선택은 네이티브 picker를 사용할 수 있으나 결과 표시는 YYYY/MM/DD（曜）다.
- 한 화면이 여러 해에 걸칠 수 있으므로 표·확정 확인에는 연도를 생략하지 않는다.
- 담당 기간은 '2026/10/26（月）〜2026/11/01（日）'처럼 양 끝 포함으로 표시한다.
- 서버의 endDateExclusive는 Repository/포맷 함수에서 의미를 분명하게 다루며 화면에서 그대로 종료일로 표시하지 않는다.
- 시간 미지정은 '時刻未設定' 또는 날짜만 표시한다. 00:00로 바꾸지 않는다.
- 용어는 当番、担当期間、実施予定、確定、未確定、対象外期間、代理、変更履歴로 통일한다.
- Text/Button/Input/Flex 등 [디자인 시스템](../architecture/design-system.md)을 사용한다.
- 이 문서는 업무 UI 계약이다. 아직 없는 다단계 폼·일정 상세 등의 컴포넌트를 카탈로그에 구현 완료로 올리지 않는다.

## 2. 목표 화면과 역할

기존 Hash Router 구조를 유지하며 아래 경로는 추가 구현할 목표다.

| 경로              | 화면        | ADMIN                            | MEMBER                    |
| ----------------- | ----------- | -------------------------------- | ------------------------- |
| /                 | 당번 스케줄 | 전체 조회, 미리보기, 확정, 변경  | 공개된 확정 일정 조회     |
| /duties           | 업무 목록   | 생성·수정·중지·종료              | 활성 업무와 안내 조회     |
| /duties/new       | 업무 생성   | 가능                             | 불가                      |
| /duties/:id       | 업무 상세   | 규칙·버전·담당·발생 건·제외·이력 | 공개 담당·수행 안내       |
| /duties/:id/edit  | 규칙 변경   | 적용일·영향 확인                 | 불가                      |
| /employees        | 직원 관리   | 등록·정보·재직 상태 변경         | 첫 단계에서는 메뉴 미노출 |
| /settings/company | 회사 설정   | 근무 요일·휴일·퇴근 시각         | 불가                      |

목록→상세→편집은 페이지로, 대타·제외·개별 발생 건 변경 같은 짧은 작업은 공통 Modal로 한다.
로그인 구현 전 화면은 개발용 관리자 상태일 뿐이다. 실제 권한은 서버에서 강제해야 한다.

## 3. 스케줄 화면

- '担当期間'과 '実施予定'를 구분한다. 주간 담당자가 매일 바뀌는 것처럼 보이게 하지 않는다.
- 기본은 이번 주와 이후 5주 범위, 회사 주 시작은 월요일이다.
- 업무 필터·조회 기간·선택한 업무는 페이지 이동 시 유지한다. 서버 결과는 Zustand에 복제하지 않는다.
- 운영 일정에는 확정된 기간·발생 건만 표시한다. 관리자 미리보기는 시각적으로 분리한다.
- 기간 행에는 업무명, 담당 범위, 담당자(사번 포함 상세), 상태, 발생 건 수, 경고를 표시한다.
- 휴일은 '会社休業日', 해당 발생 건은 '実施なし'로 표시한다. 담당자가 바뀌었다고 표시하지 않는다.
- 취소된 발생 건은 기본 목록에서 상태와 함께 보존하거나 'キャンセルを表示' 필터로 조회 가능해야 한다.
- '更新'은 명시적인 재조회이며, 실패 시 기존 결과를 '最新情報の取得に失敗しました'와 함께 유지할 수 있다.
- 새 데이터의 범위·업무가 이전 데이터와 다르면 이를 최신 조회 결과인 것처럼 표시하지 않는다.

빈 상태는 '직원 없음', '업무 없음', '확정 없음', '해당 범위 발생 건 없음'을 구분한다.
서버 실패를 '일정 없음'으로 표시하지 않는다.

## 4. 업무 생성

### 입력 단계

1. 기본 정보: 업무명(1~100자), 설명·수행 안내(0~1,000자).
2. 업무 발생: WORKDAYS/WEEKLY/DAILY_INTERVAL/MONTHLY_DAY/MONTHLY_NTH_WEEKDAY/EXPLICIT_DATES 중 선택.
3. 담당 교대: 달력 기간 또는 발생 건마다. 기간 교대는 시작일·간격·단위 설정.
4. 참여자·순서·기간별 인원: 참가자 선택, CUSTOM 순서 이동, 첫 후보 확인.
5. 휴일·중복: 기본 휴일 발생 제외, 기본 중복 허용+경고.
6. 검토: 일본어 문장 요약과 미리보기.

예: '会社の勤務日に実施 / 毎週月曜に交代 / 各1名 / 社員番号順'를 각각 보여준다.
WORKDAYS는 휴일 제외가 의미 자체이므로 휴일 수행 옵션을 잠근다. 지정 요일의 휴일 수행은 WEEKLY 등에서 선택한다.
주간 업무에 시각을 입력했다고 시각별 교대 규칙을 암묵적으로 만들지 않는다.

### 저장과 운영 시작

- 초안 저장: '下書きを保存'. 아직 배정이 확정되거나 일반 직원에게 공개되지 않는다.
- 운영 시작: '運用を開始'. 최초 규칙 버전을 만들지만 담당 확정은 별도다.
- 입력 일부가 비어 있으면 초안은 허용할 수 있으나 운영 시작 시 전체 검증을 통과해야 한다.
- 참여자 부족, 빈 요일, 잘못된 월간 규칙, 시작일 누락은 해당 입력 근처에 오류를 표시한다.
- 연산·업무 검증은 Hook이 조정하고 서버가 최종 검증한다.

## 5. 규칙 편집·참여자 변경

- '현재 적용 규칙', '변경 예정 규칙', '적용일'을 분리해서 보여준다.
- 일정·참여자·인원·순서 변경에는 적용일과 사유가 필수다.
- 설명·이름 수정은 업무 메타데이터 변경이며 규칙 순환을 재시작하지 않는다. 확정 이력의 이름 스냅샷은 유지한다.
- 주간 업무의 수요일 변경 요청이면 다음 가능한 기간 경계를 제안한다. 수요일부터 담당자를 쪼개지 않는다.
- 다음 달 이후까지 자동 배정되어 있어도, 허용된 적용 경계부터 변경 전후 미리보기와 명시적 승인으로 변경할 수 있다. 연간 조회가 적용 가능일을 뒤로 밀지 않는다.
- 과거·진행 중인 기간·보호된 수동 변경과의 충돌을 구분한다. 미래 자동 배정은 미리보기 승인 대상이며, 보호 항목을 조용히 덮어쓰는 우회는 없다.
- 기존의 다음 후보부터 이어가는 순서를 보여준다. 제외된 후보는 기존 순서상 다음 남아 있는 사람으로 넘긴다. 신규자는 사번순·지정순의 해당 위치에 편입하고, 랜덤은 기존 잔여 대기열 뒤에 추가한다. 기준 후보와 신규자의 첫 담당 위치를 미리보기에서 보여주며 재조회로 순서를 바꾸지 않는다.
- 적용 대기 버전이 있으면 추가 생성 대신 '変更予定を取り消して編集'을 제공한다. 취소 사유를 남긴다.
- 편집 내용을 떠날 때 변경사항이 있으면 폐기 확인을 제공한다. 네이티브 날짜 picker 등 시각 동작은 UI가 담당한다.

## 6. 미리보기·확정

1. 기간·업무 선택.
2. 서버 미리보기 응답 대기. 계산 중 확정 불가.
3. 기간별 후보, 발생 건 수, 적용 버전, 경고/차단 사유 표시.
4. '予定を確定' 확인 화면에서 전체 실제 저장 범위·담당·경고를 다시 표시.
5. 확인 후 서버에 한 번의 원자적 확정 요청.
6. 성공 시 확정 결과로 재조회하고 '予定を確定しました' 표시.

미리보기 만료는 목표 15분이다. 남은 시간을 초 단위로 강제 표시할 필요는 없으나 만료 후 재계산을 안내한다.
조회 범위 앞쪽 미확정 기간도 확정해야 한다면 '表示範囲より前の未確定期間も含まれます'와 전체 목록을 보여준다.
보이지 않는 행을 암묵적으로 확정하지 않는다.

| 상황              | UI 동작                                                   |
| ----------------- | --------------------------------------------------------- |
| 인원 부족         | 차단 사유와 필요한 인원 표시, 확정 비활성                 |
| 허용 중복         | 업무·직원·겹치는 기간 표시, 확인 후 진행 가능             |
| 금지 중복         | 차단. 상대 업무와 기간으로 이동할 수 있게 안내            |
| 발생 건 0개       | 주간 담당 교대는 진행됨을 경고하고 확인                   |
| 입력/선택 변경    | 이전 previewId 폐기, 다시 계산                            |
| 서버 409          | 폼·필터 보존, 최신 미리보기 재조회, 재확인 필요           |
| preview 만료      | 다시 계산. 기존 token을 자동 재사용하지 않음              |
| 네트워크 타임아웃 | 결과 미확정 안내. 동일 operationId로 결과 확인/재시도     |
| 일부 행 오류      | 전부 저장되지 않았음을 표시. 부분 성공처럼 보이지 않게 함 |

경고는 색만으로 전달하지 않고 제목·문구·해당 행을 제공한다.
이름이 같은 직원은 사번으로 구분한다. 모호한 인덱스만으로 배정 결과를 연결하지 않는다.

## 7. 대타·제외·발생 건 변경

### 대타

- 현재 담당자·기간·변경 후 직원·사유를 표시한다.
- 후보의 부적격 사유(제외·비활성·금지 중복)는 숨기기만 하지 않고 설명할 수 있어야 한다.
- '今回の担当枠のみ変更します。以降の順番は変わりません。'를 안내한다.
- 진행 중인 기간은 앞으로 남은 업무부터 변경됨을 표시한다. 이미 지난 발생 건의 담당 표시를 덮어쓰지 않는다.
- 과거 담당 수정은 첫 단계에서 제공하지 않는다.

### 휴가·출장에 따른 담당 변경

- 일정은 사전에 배정하고, 이후 휴가·출장이 정해지면 해당 일정의 담당자를 변경한다.
- 일정 목록에서 대상외 기간 등록은 제공하지 않는다. 휴가 기간을 등록해 여러 일정을 조정하는 기능은 후속 과제로 둔다.
- 담당자 옆에 「担当者を変更」을 표시한다. 과거 일정은 「変更履歴」로 안내한다.
- 변경창에 당번·현재 담당자·대상 날짜 또는 담당 기간·변경 후 담당자·사유·변경 이력을 표시한다.
- 기간 담당은 해당 담당 기간에, 회차 담당은 해당 회차에 변경을 적용하며 이후 순서는 유지한다.
- 기존 대상외 데이터와 서버 처리 기능은 유지한다. 이번 UI 정리로 기존 배정을 재계산하거나 삭제하지 않는다.

### 개별 발생 건

- 회의 일자 변경·단일 취소는 업무 전체 중지와 구분한다.
- 원래 날짜·변경 날짜·사유·담당 영향 표시.
- 기간 경계를 넘어 이동하면 새 담당자가 누구인지 확인받는다.
- 대상 기간이 미확정이면 먼저 확정하도록 차단한다.
- 회사 휴일 자동 이동 옵션은 기본 폼에 만들지 않는다.

## 8. 중지·종료·직원 상태

- 중지: '一時停止'. 재개 가능, 적용일 이후 새 계획 없음.
- 종료: '終了'. 이력 보존, 적용 후 되돌리기 불가. 이름만 바꾼 재활성으로 처리하지 않는다.
- 중지·종료에 확정 일정이 걸리면 영향을 표시하고 차단한다. 사용자 모르게 미래 담당을 삭제하지 않는다.
- 종료 확인은 목표 ConfirmDialog(role=alertdialog)로, 이름·적용일·이력 보존을 명시한다.
- 직원 비활성은 'メンバーを削除'가 아니라 '無効にする'. 적용일과 영향 목록 확인.
- 직원 사번·이름 변경은 직원 식별자(id)를 바꾸지 않는다.

## 9. 회사 캘린더

- 기본 근무 요일과 날짜별 근무/휴무 예외를 구분한다.
- 화·수 휴무를 등록하면 월·목·금 발생, 주간 담당 유지, 다음 주 원래 교대라는 설명 예시를 제공한다.
- 캘린더 변경의 영향 미리보기에는 확정된 미래 발생 건의 취소/추가 후보를 보여준다.
- 미래 확정 일정에 영향이 있으면 관리자 확인 후 원자적으로 반영한다.
- 과거 날짜 변경은 첫 단계에서 차단한다.
- 퇴근 시간 미설정은 '未設定'. 메일·Pepper 알림 활성화 전 입력하게 한다.

## 10. 접근성·비동기·화면 계약

- 로딩·빈 결과·조회 오류·저장 오류를 구분한다. 각 페이지는 의미 있는 h1을 하나 갖는다.
- 필드는 접근 가능한 label, 오류는 필드 연결 + role=alert, 성공은 role=status를 사용한다.
- 키보드로 모든 버튼·폼·대화상자에 접근할 수 있어야 한다. 모달 종료 후 실행 버튼에 포커스를 복원한다.
- 저장 중 같은 명령을 다시 보내지 않으며 submit·닫기·ESC를 막는다.
- POST 성공 여부가 불명확하면 새 operationId로 자동 재시도하지 않는다.
- 조회 취소는 오류 토스트가 아니다. 오래된 조회 응답이 최신 선택을 덮어쓰지 않아야 한다.
- UI는 request DTO 생성·날짜 연산·대상 필터링·저장 후 이동을 직접 처리하지 않고 Hook 결과/handler에 연결한다.
- 최신 [API 계약](../../../server/docs/design/api-contract.md)의 warnings와 violations는 구조화된 코드로 판정한다.
  일본어 message 문자열 비교로 로직을 분기하지 않는다.

미리보기 회차 수는 참가자 수로 제한하지 않는다. 최소 전체 한 바퀴와 등록된 개별 개최일 전체를 포함하며, 추가로 previewCount(최대 200회)를 지정할 수 있다. 예를 들어 5명·12개 개최일이면 12회 모두 1→2→3→4→5→1 순서로 계산한다. 미리보기 회차 수를 늘려도 seed와 기존 순번은 유지되며 업무 종료 횟수를 뜻하지 않는다.

## 담당 기간 요약 표시 — 현재 구현

- CALENDAR 교대는 동일 업무·교대 키·기간·저장된 담당자 슬롯이 같은 실행일을 한 행으로 묶는다. 주간/월간 담당자를 날짜마다 중복 표시하지 않는다.
- 첫 열 「実施日」에는 조회 범위 내 실제 실행일의 처음~마지막 날짜를 표시한다. 서버가 반환한 실행일을 사용하며 회사 휴일은 제외한다. 월~금 업무에서 토·일을 실행일처럼 표시하지 않으며, 주말 실행 업무는 실제 실행 날짜를 그대로 포함한다. 실행·휴일 수는 ‘表示範囲内’로 표시한다. 담당 교대의 원래 시작일~종료일은 변경하지 않고 펼친 상세의 「交代の区切り」로 구분한다.
- ‘実施日を確認’을 펼치면 조회 범위 내의 실행일·회사 휴일·날짜별 경고를 확인할 수 있다. 휴일이나 주말까지 매일 실행한다고 표시하지 않는다.
- OCCURRENCE 교대는 같은 사람이 연속으로 담당해도 회차별 행을 유지한다. 다른 업무·다른 교대 기간·다른 담당자 슬롯은 합치지 않는다.
- 요약 행의 대타·이력은 기존 담당 기간 슬롯을 사용한다. 기간 중 일부 날짜의 중복 경고도 요약에서 누락하지 않는다.

## 홈의 정보 우선순위 — 현재 구현

- 홈 상단은 오늘의 실행 담당자, 앞으로 6주 이내 각 업무의 다음 교대/개최, 날짜 미정·담당 경고 순으로 보여준다. 장식용 슬로건이나 의미 없는 통계 카드는 사용하지 않는다.
- 오늘 담당은 실제 오늘의 실행 건 중 회사 휴일이 아닌 건이다. 기간 담당자를 오늘 실행한 것으로 추측하지 않는다. 다음 교대는 실제 담당자가 바뀌는 첫 미래 기간, 회차 업무는 다음 개최일을 표시한다.
- 요약의 날짜 범위는 항상 일본 업무일 기준 오늘~41일 후다. 아래 목록을 과거·미래로 필터링해도 오늘의 담당이 바뀌지 않는다. 조회 범위가 요약 범위를 포함하면 같은 서버 응답을 재사용하고, 그렇지 않으면 요약 범위만 별도로 가져온다.
- 목록의 기간 조작은 ‘今日から6週間’·‘今月’ 빠른 선택과 접힌 사용자 날짜 입력으로 제공한다. 업무 필터는 목록에만 적용한다.
- 목록은 기존 담당 기간 묶음과 날짜별 상세 펼침을 유지한다. 날짜 미정 회차의 개최일 등록, 대타·이력, 제외 기간, 회사 휴일 관리 기능은 유지한다. 이전 형식 데이터는 접힌 별도 영역에서 열 수 있다.
- 읽기 오류를 ‘오늘 일정 없음’으로 표시하지 않는다. 로딩·조회 실패·실제 빈 일정은 분리한다.
- 좁은 화면은 오늘/다음/확인 항목을 세로로 배치한다. 표만 내부 가로 스크롤하며 페이지 전체를 넓히지 않는다.

## 시각 디자인 기준

[디자인 시스템 정책](design-system.md)의 Neutral Workplace를 사용한다. 홈의 정보 우선순위와 기존 생성·배정 동작은 유지하며, 1px 경계·4~6px 모서리·조밀한 간격·중립적인 일본어 문구·숫자 고정폭을 공통으로 적용한다. 색상과 인터랙션 컴포넌트의 상세 구현은 컴포넌트 카탈로그에 기록한다.

## 홈의 시각적 우선순위

오늘의 업무명과 담당자를 날짜·설명·관리 버튼보다 먼저 읽도록 배치한다. 날짜는 보조 정보로 표시하고 담당자 이름을 가장 크게 표시한다. 다음 교대는 현재 담당 → 다음 담당으로 연결해 읽을 수 있게 한다. 날짜 미정·경고 항목은 1px 경계 영역과 명시적인 조작 버튼으로 구분한다. 중립 팔레트·기존 밀도와 업무 동작은 유지한다.

## 담당자 검색·필터 — 현재 구현

- 예정 목록은 조회 기간·업무·담당자 조건을 AND로 적용한다. 검색 범위는 현재 조회 기간이며 과거 내역은 ‘今月’ 또는 사용자 기간으로 조회한다.
- ‘氏名・社員番号で検索’는 이름·사번 부분 일치를 지원한다. 전각 영숫자는 NFKC로 정규화하고 대소문자·이름 사이 공백을 구분하지 않는다. 공백으로 나눈 검색어는 같은 담당자 안에서 모두 만족해야 한다.
- ‘担当者で絞り込む’에서 직원 ID를 선택하면 해당 직원이 맡은 행만 보여준다. 동명이인은 사번으로 구분한다. 비활성 직원도 과거 기록 조회를 위해 선택 가능하며 ‘無効’를 표시한다.
- 검색어를 입력하면 정확한 직원 선택을 해제하고, 직원을 선택하면 검색어를 지운다. 업무·날짜 조건은 유지한다. ‘絞り込みを解除’는 업무·담당자·검색어만 해제하고 날짜 범위는 유지한다.
- 주간/월간 일정은 먼저 담당자 조건을 적용한 뒤 기존 담당 기간 기준으로 묶는다. 공동 담당자는 숨기지 않고 함께 표시하며 검색에 일치한 직원만 굵게 표시한다.
- 기존 형식으로 보존한 담당 기간에도 같은 업무·직원·검색어 조건을 적용한다. 변경 이력 자체의 전문 검색이 아니라 현재 저장된 담당자의 내역 필터다.
- 필터 선택은 Zustand UI 상태로 화면 이동·재조회 중 유지한다. 새로고침 이후 영속 저장하거나 로그인 사용자로 자동 선택하는 기능은 없다.
- 홈 상단 오늘/다음/확인 항목은 전체 기준이다. 상단 경고에서 ‘予定を確認’으로 목록에 이동하면 해당 업무를 보이도록 직원·검색어 조건을 해제한다.
- 검색 결과 0건은 ‘条件に一致する担当はありません。’과 해제 버튼으로 표시한다. 결과 없음 상태에서 새 당번 생성으로 유도하지 않는다.
- 검색은 Hook과 순수 필터 함수에서 수행하고 UI는 값과 이벤트만 연결한다. 검색·선택 때문에 API를 다시 요청하거나 배정 데이터를 변경하지 않는다.

## 동일 이름의 업무 필터

업무 셀렉트는 같은 이름의 서로 다른 당번 ID를 이름당 하나의 선택지로 묶는다. 예를 들어 이전 형식과 신규 형식으로 각각 생성한 定例会를 선택하면 해당 이름 그룹의 모든 ID에 해당하는 담당을 조회한다. 목록 행·담당 슬롯·변경 이력은 합치거나 삭제하지 않는다. 기존 선택 ID가 그룹의 대표 ID가 아니어도 같은 그룹 선택값으로 표시하고 조회한다. 직원·검색어·기간 조건도 같은 그룹 전체에 AND로 적용한다.

## 조회 기간 버튼의 선택 상태

기간 버튼은 날짜 값의 일치 여부만으로 활성화하지 않고 선택 모드(upcoming/month/custom)를 별도로 보관한다. ‘期間を指定’를 누르면 날짜를 바꾸기 전에도 빠른 선택을 해제하고 사용자 기간 버튼을 활성화한다. 편집 영역을 닫아도 사용자 기간 선택은 유지한다. 빠른 선택을 누르면 해당 버튼 하나만 활성화하고 편집 영역을 닫는다. 수동 날짜 변경은 custom 모드이며 날짜가 우연히 이번 달/6주와 같아도 빠른 선택으로 돌아가지 않는다. 모드는 UI 상태로 화면 이동 중 유지한다.

## ホームと予定一覧の役割

- ホーム（/）は今日の担当、6週間以内の次の交代・開催、確認が必要な予定を表示する。予定一覧の期間・担当者フィルターには影響されない。
- 予定一覧（/schedule）は期間、当番、メンバーで検索し、担当変更や履歴確認を行う画面とする。
- 当番設定の「予定を確認」はその当番のみを表示する。同名の別当番は含めない。通常の当番フィルターでは従来どおり同名の当番をまとめる。
- 登録などの成功通知は5秒後に自動で消す。同じ通知を再表示した場合も5秒間表示する。画面移動で表示時間をリセットしない。エラー通知は自動で消さない。

## 当番の削除

- 当番設定の各カードに「削除」を配置する。確認ダイアログに当番名・開始日・参加人数を表示し、同名の別当番と区別する。
- 「削除する」で明示的に確定するまでAPIを呼ばない。削除中は重複送信とダイアログを閉じる操作を無効にする。失敗時はダイアログ内にエラーを表示し、再試行できる。
- 対象IDの当番設定・実施予定・担当割当・対象外期間・変更履歴をトランザクション内で削除する。復元不可。メンバー・他当番・会社休業日は保持する。
- 通常のルール変更では確定済み予定を保持する原則は変えない。削除は影響を表示したうえでユーザーが明示した場合に限る。
- API: DELETE /api/duties/{id}。成功204、対象なし404。削除後は一覧・ホームを再取得する。

## 当番詳細・年間予定

- 当番設定の「詳細・編集」から /duties/:dutyId に移動する。サイドメニューの当番設定を選択状態にする。
- 名前・説明・開始日・実施日ルール・交代ルール・担当順・人数・参加メンバーを表示する。名前・説明は「基本情報を編集」で変更する。
- 既定は日本時間の今年1/1〜12/31。前年・翌年・今年・年選択を提供する。選択年はURLのyearで保持する。予定一覧の期間・人物フィルターとは独立させる。
- 月次・個別開催日の当番は1〜12月の月別一覧を表示し、各開催日と担当者を並べる。未定の回は年に帰属させず「開催日未定」にまとめる。その他の当番は担当期間でまとめた年間一覧を使用する。
- 各回の開催日登録・変更、担当者変更・履歴は既存の共通ダイアログを使用する。開催日の変更で回の順番・担当者を変えない。
- 今回の編集範囲は名前・説明・個別開催日・担当者変更。参加者や実施・交代ルールの変更は適用開始日と既存割当維持の設計を伴う後続作業とする。
- 基本情報の更新では編集開始時の名前・説明と照合し、別の更新があれば409として上書きを防ぐ。予定・担当順・履歴は再作成しない。

## 空き月からの開催日登録

- 「開催日を回ごとに指定」の当番だけ、予定のない月に「開催日を登録」を表示する。月次繰り返しルールは変更しない。
- 既存の未定回から、その月と前後の開催順に合う最も早い回を選ぶ。新しい回を挿入したり担当順を組み直したりしない。
- ダイアログで当番・開催回・担当者・対象月を示し、日付は今日・当番開始日・前回の翌日以降、次回の前日以前、対象月内に制限する。
- 過去の月、または順番に合う未定回がない月では登録を無効にし、理由を表示する。
- 月別表示は分類であり、月1回という上限は設けない。未定一覧からは既存どおり任意の許可日を登録できる。保存には既存の開催日更新APIを使用し、回の番号・担当者・以降の順番を維持する。

## メンバーの編集と削除（現行）

- メンバー一覧に「編集」「有効にする／無効にする」「削除」を表示する。編集対象は名前（80文字以内）と社員番号（40文字以内）。登録・編集は共通入力と共通検証を使う。
- 編集はID・状態・参加当番・保存済み担当を維持する。表示名と社員番号は既存予定・履歴でも最新情報を表示する。社員番号順は未保存の担当計算に影響し、保存済みの順番は組み直さない。
- 元の名前・社員番号を照合し、同時更新は409で通知する。重複社員番号も拒否する。失敗時は入力内容を残す。
- 削除確認前にサーバーで関連の有無を確認する。参照がある場合は削除を無効にし、「無効にする」を案内する。確認の通信失敗は再確認を提供する。
- 当番参加・対象外期間・旧形式の担当割当・新形式の担当枠・両形式の変更履歴（変更前／変更後の両方）に関連がないメンバーだけ物理削除できる。実行時も再検証し、関連データを連鎖削除しない。
- 退職者の履歴を残す操作は従来どおり無効化。物理削除は誤登録など関連のないメンバーの整理に使う。削除確定前に復元不可を明示する。

## 更新時の表示維持

- 初回取得（loading）と、同じ検索条件での再取得（refreshing）を区別する。同じ条件では成功済みの一覧・カード・詳細を表示したまま更新する。空の一覧も取得済みとして扱う。
- 有効／無効、編集、担当変更、開催日保存、手動更新で画面全体を読み込み表示に置き換えない。更新中の操作は無効にし、既存DOM・展開状態・スクロール位置を維持する。
- 別の当番・年・期間へ変更した場合は別の問い合わせとし、以前の結果を新しい条件のデータとして表示しない。中断済みの応答で最新結果を上書きしない。
- 再取得に失敗しても最後の成功データを残し、エラーを表示して更新の再試行を可能にする。
- 成功通知は共通レイアウトの画面右下に固定表示する。本文の高さを変えず、5秒後または閉じる操作で消える。保存後も開いたままのダイアログ内では保存結果も表示する。

규칙 편집의 합의와 미합의 항목은 [참가자·규칙 변경 정책](../../../docs/policies/rule-change-policy.md)을 기준으로 한다. 참가자·순서·인원·상태 변경 검토는 구현했다. 개최일 규칙 변경은 별도 범위다.

수동 변경 보호 충돌은 규칙 변경 검토 화면 안에서 건별 대체 담당자를 선택해 함께 저장하는 방식으로 합의되었다. 해결 전에는 저장을 막고 해당 건으로 안내하며, 일정 화면으로 돌아가 선행 수정하도록 요구하지 않는다. 퇴사·재활성화의 기본 배정 동작은 [규칙 변경 정책](../../../docs/policies/rule-change-policy.md)을 따르며, 실제 범위와 보호 제한은 [구현 명세](../../../docs/policies/assignment-change-implementation.md)를 따른다.

무효·유효 전환의 기본 배정 동작은 사용자 확인을 받았다. 무효화하면 다음 담당자를 앞으로 당겨 빈 주·회차를 남기지 않고, 유효화하면 원래 순서에 다시 넣어 미래 배정을 복원한다. 원래 위치를 보존한다는 것은 복원용 정보 보관이지 일정의 빈칸 유지가 아니다. 두 작업 모두 영향 미리보기·승인 후 적용하며, 유효화 사용자가 별도 취소 기능이나 명단 삭제·재등록을 해야 원래 자리로 돌아가는 UX는 제공하지 않는다. 과거·진행 중인 담당과 수동 보호는 유지하고 미래 충돌을 검토 화면에서 해결한다. 공통 검토 화면에서 상태와 미래 배정을 원자적으로 저장하며, 동시 수정 시 재확인을 요구한다.

## 担当予定の範囲

生成時に運用終了と今回の担当期間を別々に指定する。実際の最終担当期間と件数を確認して保存する。範囲外は自動作成せず、詳細の「担当予定を追加」でプレビュー後に延長する。個別開催日の未定回は入力・追加した回数だけを作成する。

## 予定の経過と日付変更

過去の予定は「過去」と控えめな背景、進行中の期間は「担当中」、今日の開催は「本日」で区別する。日付から完了とは判定しない。未来の開催日は理由と変更前後の確認を経て適用する。週・月の担当期間変更と日別の代理担当管理は提供しない。[日時変更ポリシー](../../../docs/policies/schedule-date-policy.md)を参照。

## 現在の担当者を参加メンバーから除外

除外した人が現在の担当なら、今回の終了まで継続するか、本日から残りを別メンバーへ引き継ぐか選ぶ。初期選択は継続。参加名簿は承認時に更新し、継続する人は「今回のみ…まで担当」と別に表示する。引継ぎ先は次の自動担当順に反映し、昨日までの担当を維持し、変更後の担当と併せて検討画面で確認する。一般の期間編集・日別代替管理は追加しない。[現在担当引継ぎ](../../../docs/policies/current-assignment-handover.md)を参照。

ホームの「今日の当番」は会社休業日を「休業日」と表示し、登録された休業日名を示す。通常の当番が休みであることと予定未登録を区別する。休業日にも実施する予定は引き続き表示する。

現在の週・月担当は、ホーム・予定一覧・詳細の「担当者を変更」からも共通の引継ぎ検討を使う。参加名簿は変えず、本日から担当し、引継ぎ先の次の自動担当を消費して後続を繰り上げる。手動指定は検討画面で保護・解消する。未来の単発変更は従来通り今回のみ。

同じ担当期間内に、参加除外した元の担当者を再追加すると、本日から元の担当へ戻す。名簿は元の担当者を引継ぎ先の前に戻し、引継ぎ先は次の自動担当へ戻す。検討画面で現在・今後の担当を確認して適用する。昨日までの記録と手動指定の保護は維持する。元の期間が終了した場合は現在担当を変更しない。

## Excel 다운로드 — 현재 구현

당번 상세에서 보고 있던 연도를 기본으로 기간을 선택한다. 교대 방식에 맞는 추천 서식을 제공하되 변경 가능하다. 미배정 구간과 미정 회차의 포함 범위는 다운로드 전에 표시한다. 저장 중 중복 다운로드·닫기를 막고 오류는 모달에서 표시한다. 성공하면 파일을 내려받고 창을 닫으며 당번 설정이나 일정을 변경하지 않는다. 상세는 [Excel 내보내기 정책](../../../docs/policies/excel-export-policy.md)을 따른다.
