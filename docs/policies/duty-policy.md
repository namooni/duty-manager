# 업무·당번 배정 정책

상태: 다음 구현 단계의 기준안. '사용자 합의' 항목 외 상세 운영값은 이 문서에서 제안한 기본값이다.
현재 구현과의 차이는 [구현 계획](../plans/implementation-roadmap.md)을 따른다.

## 1. 기본 범위와 용어

- 한 회사의 사내 운영을 대상으로 한다. 다중 회사 SaaS·교대근무·급여 계산은 범위 밖이다.
- UI·서버 안내는 일본어, 업무 날짜·주차는 Asia/Tokyo 기준이다. 한 주는 월요일~일요일이다.
- 회사 퇴근 시간은 설정값이며 임의로 18:00로 확정하지 않는다. 알림 구현 전 실제 값을 입력한다.

| 용어                    | 의미                                                  | 예                          |
| ----------------------- | ----------------------------------------------------- | --------------------------- |
| 업무 Duty               | 반복적으로 분담할 일                                  | 朝会の司会・議事録          |
| 규칙 버전 RuleVersion   | 특정 날짜부터 적용할 일정·참여자·순서의 스냅샷        | 11/2부터 참가자 5명         |
| 담당 기간 Period        | 같은 담당자가 역할을 유지하는 구간                    | 월요일부터 다음 월요일 직전 |
| 업무 발생 건 Occurrence | 실제 수행해야 하는 한 번의 업무                       | 목요일 09:00 아침회의       |
| 담당 슬롯 Assignment    | 특정 기간을 맡는 직원 1명                             | 그 주의 1번 담당            |
| 제외 Exclusion          | 업무별로 자동 배정에서 제외할 직원·날짜 구간          | 휴가·출장                   |
| 확정 Confirm            | 배정과 계산 결과를 저장해 운영 일정으로 공개하는 행위 | 다음 4주 확정               |

담당자와 업무 발생일은 별개다. 평일마다 회의가 있어도 담당자는 매주 한 번만 교대할 수 있다.
매일의 발생 건을 각기 다른 직원에게 나누려면 교대를 '발생 건마다'로 선택한다.

## 2. 세 가지 업무의 설정 예시

아래 요일·시각은 회사의 실제 일정이 아닌 설명용 예시다.

| 업무                 | 발생 규칙                       | 교대 규칙        |
| -------------------- | ------------------------------- | ---------------- |
| 아침회의 진행·회의록 | 회사 근무일마다, 시각 선택      | 월요일 시작 1주  |
| 쓰레기 배출          | 지정 요일(예: 화·금), 시각 선택 | 월요일 시작 1주  |
| 정례회 회의록        | 매월 제N요일 또는 개별 지정일   | 실제 발생 건마다 |

한 직원이 진행과 회의록을 함께 맡으면 한 업무로 만들고, 따로 맡으면 두 업무로 만든다.
쓰레기 수거일이 회사 근무일과 다르면 그 업무에 한해 휴일 수행을 명시적으로 허용할 수 있다.

## 3. 회사 근무일과 휴일 — 사용자 합의

- 기본 근무 요일은 월~금이다. 회사 설정으로 변경할 수 있다.
- 날짜별 예외는 근무일 강제 지정 또는 휴무 지정 중 하나다. 날짜별 예외가 기본 요일보다 우선한다.
- 공휴일을 임의로 추정하지 않는다. 첫 단계에서는 관리자가 회사 캘린더에 등록한다.
- 기본적으로 휴일에는 업무 발생 건이 없다. 자동으로 다른 날짜로 옮기거나 보충하지 않는다.
- 휴일 때문에 담당 기간·교체일·다음 사람의 순서를 밀지 않는다.

예: 2026-10-27(화)·28(수)이 회사 휴무인 주간 아침회의.

| 날짜        | 업무 발생     | 담당                 |
| ----------- | ------------- | -------------------- |
| 10/26 월    | 있음          | A                    |
| 10/27 화    | 없음          | A의 담당 기간은 유지 |
| 10/28 수    | 없음          | A의 담당 기간은 유지 |
| 10/29 목    | 있음          | A                    |
| 10/30 금    | 있음          | A                    |
| 11/2 월부터 | 근무일에 발생 | 다음 차례 B          |

A는 월·목·금에만 수행한다. 빠진 이틀을 다음 주에 수행하지 않는다.
주 전체가 휴무여도 달력 기준 주간 교대는 진행한다. 해당 기간에 발생 건이 0개임을 미리보기에서 알리고, 수행 횟수 보상은 자동으로 하지 않는다.

업무별 holidayPolicy는 기본 COMPANY_WORKDAYS, 예외적으로 ALLOW_ON_HOLIDAYS다.
정례회 등을 다른 날짜에 실제 개최하려면 관리자가 개별 발생 건을 명시적으로 변경한다.
'휴일 취소 후 자동 이동'이라는 복합 동작은 제공하지 않는다.

회사 캘린더 변경이 이미 확정된 미래 발생 건에 영향을 주면 영향 목록과 취소 예정 건수를 보여주고 별도로 확인한다.
업무 발생 건만 변경하며 기간 담당자는 보존한다. 과거 발생 건은 소급 변경하지 않는다.

## 4. 발생 규칙과 담당 교대

### 발생 규칙

- WORKDAYS: 회사 근무일마다.
- WEEKLY: 기준 주부터 N주마다 지정 요일 집합.
- DAILY_INTERVAL: 기준 날짜부터 N일마다. 달력일을 센 뒤 휴일 정책을 적용한다.
- MONTHLY_DAY: 기준 월부터 N개월마다 지정 일자. 말일을 넘으면 CLAMP_TO_LAST_DAY 또는 SKIP을 명시한다.
- MONTHLY_NTH_WEEKDAY: 기준 월부터 N개월마다 첫째~다섯째/마지막 지정 요일. 존재하지 않는 다섯째는 건너뛴다.
- EXPLICIT_DATES: 관리자가 입력한 개별 날짜 목록.

WORKDAYS는 회사 근무일 자체가 발생 조건이므로 holidayPolicy를 COMPANY_WORKDAYS로 고정한다.
휴일에도 수행할 지정 요일 업무는 WEEKLY 등으로 설정하고 ALLOW_ON_HOLIDAYS를 명시한다.

시각은 선택이다. 시각이 없으면 날짜만 있는 업무로 표시하고 임의로 자정 업무라고 안내하지 않는다.
첫 단계는 분·시간마다 반복, 복잡한 RRULE 문자열, 근무일 N일 간격을 제공하지 않는다.

### 교대 규칙

- CALENDAR_INTERVAL: anchorDate부터 N일/N주/N개월 간격의 담당 기간.
- EACH_OCCURRENCE: 취소되지 않은 실제 업무 발생 건마다 교대.
- CALENDAR_INTERVAL 기간은 내부적으로 [startDate, endDateExclusive)다.
- 월 단위는 원래 anchorDate 기준으로 계산한다. 1/31 → 2/28 → 3/31처럼 누적 보정하지 않는다.
- UI 종료일은 endDateExclusive 하루 전까지로 표시한다.
- N은 1~365, 기간별 인원은 1~20, 참여자는 업무당 최대 200명으로 시작한다.

개별 발생일을 다른 담당 기간으로 이동하면 새 담당 기간의 확정된 담당자가 맡는다.
대상 기간이 미확정이거나 휴일 금지 조건에 걸리면 이동을 차단하고 먼저 일정 확정/다른 날짜 선택을 안내한다.
기존 담당자를 유지하려면 대상 기간의 대타 변경을 별도로 수행한다. 발생 건 이동만으로 대타를 암묵적으로 만들지 않는다.
EACH_OCCURRENCE는 발생 건의 식별자·담당자를 유지한 채 날짜를 이동하고 제외·중복을 재검증한다.

최초 운영 시작일은 회사 기준 오늘 이후로 지정한다. 기간 교대의 최초 anchorDate는 그 시작일과 일치시킨다.
오늘 시작하는 경우 이미 시작한 업무 발생 건을 새로 만들지 않는다. 담당 기간은 유지하되 앞으로 남은 발생 건만 확정한다.
이후 규칙 변경은 오늘보다 뒤의 허용 경계에서만 적용한다. 과거 미확정 구간을 새로 만들어 수행 이력처럼 표시하지 않는다.

## 5. 참여자와 순환

- 사번은 문자열이며 앞뒤 공백을 제거한다. 첫 단계의 허용 문자는 영문·숫자·하이픈·밑줄, 최대 40자다.
- 사번의 대소문자는 구분하지 않고 정규화한다. 화면에는 원래 입력 표기, 정렬·중복 판정에는 정규화 값을 사용한다.
- 사번 정렬은 정규화 문자열 오름차순이다. 숫자처럼 정렬하지 않으므로 001, 002처럼 길이를 맞춘다.
- 표시 이름은 최대 80자이며 중복 가능하다. 선택 화면에는 사번을 함께 표시한다.
- EMPLOYEE_NUMBER: 규칙 버전에 저장한 사번 정렬 스냅샷.
- CUSTOM: 규칙 저장 시 명시한 순서.
- SHUFFLED_ROUND: 버전에 저장한 seed와 algorithmVersion으로 재현 가능한 한 바퀴 랜덤.
- 단순 매회 독립 추첨은 첫 단계에서 제공하지 않는다.
- 한 기간 안에서 같은 직원을 두 슬롯에 넣을 수 없다.
- 제외·복수 담당·대타가 있으면 실제 수행 횟수는 완전히 같지 않을 수 있다. 부담 점수 최적화·자동 보상은 후속 기능이다.

조회·미리보기·새로고침은 순환 상태를 소비하지 않는다. 확정만 다음 순환 상태를 저장한다.
대타·발생 건 취소는 확정 당시 저장된 순환 상태를 되감지 않는다.
랜덤의 여러 명 배정에서 다음 라운드의 같은 사람이 중복 후보가 되면 다음 기간으로 미뤄 큐에 보존한다.

## 6. 제외·직원 비활성

- 제외 범위는 업무별, 시작일·종료일 포함이다. 종료일은 시작일 이상, 한 건은 최대 367일이다.
- CALENDAR_INTERVAL은 제외 기간이 담당 기간과 하루라도 겹치면 해당 기간 전체에서 제외한다.
- EACH_OCCURRENCE는 실제 발생 날짜와 겹치는지를 판단한다.
- 제외된 직원의 차례를 다음 주에 우선 보충하지 않는다.
- 제외는 추가·수정·취소 가능하며 사유와 이력을 남긴다.
- 제외 변경으로 확정 담당자가 부적격해지면 자동 재배정하지 않고 차단한다. 먼저 대타를 지정한다.
- 확정 담당자가 아닌 사람의 제외 변경은 확정 결과·저장된 순환 상태를 바꾸지 않는다.
- 직원 비활성은 적용 시작일을 지정한다. 기존 담당 이력은 유지하고 미래 미확정 배정에서 제외한다.
- 비활성 적용 이후의 미래 자동 배정은 대상자를 제외하고 이후 담당을 앞으로 당겨 빈 기간을 남기지 않는다. 유효화하면 복원용 원래 순서를 참고해 미래 배정을 복원한다. 두 작업 모두 영향 미리보기·명시적 승인으로 반영하며, 과거·진행 중인 기간·수동 보호를 자동 덮어쓰지 않는다. 충돌은 검토 화면에서 대체 담당자를 정해 함께 처리한다. [무효·유효 전환 정책](rule-change-policy.md)의 합의와 미구현·추가 결정 항목을 구분한다.

## 7. 여러 업무의 중복 — 사용자 합의

| 업무 설정                 | 의미                                                                         |
| ------------------------- | ---------------------------------------------------------------------------- |
| ALLOW_WITH_WARNING (기본) | 같은 사람의 다른 업무 담당이 겹쳐도 저장 가능. 미리보기와 확정 확인에서 경고 |
| FORBID                    | 그 업무가 관여하는 겹침을 차단. 대타 변경에도 동일 적용                      |

- '중복'은 담당 기간의 날짜 구간 겹침이다. 같은 시각에 발생했는지만 보지 않는다.
- 서로 다른 두 업무 중 어느 한쪽이라도 FORBID이면 차단한다.
- 허용 경고는 확인 후 진행할 수 있다. 인원 부족·금지 중복은 확인 버튼으로 우회할 수 없다.
- 잠정 미리보기는 다른 요청의 인원을 예약하지 않는다. 확정 직전에 최신 확정 배정과 재검증한다.
- 허용하는 업무도 같은 기간 안의 직원 중복은 항상 금지다.

## 8. 규칙 버전·적용일 — 2026-10-27 사용자 합의 반영

미래 재배정과 다음 차례 연속성은 [참가자·규칙 변경 정책](rule-change-policy.md)을 우선한다. 세부 미합의 항목과 현재 미구현 범위도 해당 문서에서 구분한다.

업무명·설명은 메타데이터로 수정 가능하며 순환을 다시 시작하지 않는다. 확정 이력의 이름·설명 스냅샷은 유지한다.

- 초안은 편집할 수 있다. 운영을 시작하면 규칙 본문·참여자·정렬 스냅샷을 직접 덮어쓰지 않는다.
- 변경은 새 버전으로 만들고 적용일과 사유를 입력한다.
- CALENDAR_INTERVAL은 기존 담당 기간 경계에서 적용한다. 진행 중인 한 주를 중간에 쪼개지 않는다.
- 미래의 기존 자동 배정도 변경 전후 미리보기와 사용자 명시적 승인으로 변경할 수 있다. 적용일을 마지막 저장·확정 배정 이후로만 제한하지 않는다. 과거·진행 중인 기간·보호된 수동 변경을 자동 덮어쓰지 않는다.
- EACH_OCCURRENCE는 아직 시작하지 않은 회차부터 적용할 수 있다. 참가자·배정 방식만 바꾸는 경우 개최일·회차 식별자는 유지한다.
- 한 업무에 적용 대기 버전은 최대 하나다. 수정하려면 기존 대기 버전을 사유와 함께 취소하고 다시 만든다.
- 이전 버전의 본문은 불변이다. 유효 구간을 닫거나 대기 버전을 취소하는 메타데이터 변경은 감사 기록을 남긴다.
- 새 버전을 저장해도 순환을 명단 첫 번째부터 재시작하지 않는다. 적용 경계의 다음 후보와 이어지는 순서를 편집 화면에서 보여준다.
- 기존의 다음 차례가 첫 후보이며, 그 사람이 새 명단에서 제외되면 기존 순서상 다음 남아 있는 사람부터 이어간다. 조회 범위나 마지막 저장 배정일로 다음 차례를 결정하지 않는다.
- 신규 참가자는 사번순·지정순에서는 새 명단의 해당 위치에 편입하되 기존 다음 후보부터 이어간다. 랜덤에서는 현재 한 바퀴의 기존 잔여 대기 순서를 유지하고 신규자를 뒤에 추가한다. 조회로 미리 저장된 미래 전체의 끝까지 합류를 미루거나 기존 잔여 순서를 재추첨하지 않는다.

### 일시 중지·종료

중지·재개·종료도 적용일이 있는 버전 변경으로 취급한다.
중지 동안 새 발생 건·배정을 만들지 않는다. 재개 시 시작일과 초기 순서를 다시 확인한다.
이미 적용된 종료(ARCHIVED)는 되돌리지 않으며 재사용은 새 업무 복제로 한다. 이력 조회는 계속 가능하다. 아직 적용 전인 종료 예정은 대기 버전 취소 규칙으로 취소할 수 있다.
확정 기간과 겹치는 중지·종료는 차단한다. 향후 일괄 취소 기능이 생기기 전까지 자동 삭제하지 않는다.

## 9. 미리보기·확정·변경

- 미리보기는 임시이며 운영 일정으로 공개하지 않는다.
- 확정은 업무별로 첫 미확정 기간부터 연속해서 진행한다. 중간 기간을 비워 순환 상태를 모호하게 만들지 않는다.
- 조회 범위보다 앞선 미확정 기간도 확정 대상이면 전체 목록과 범위를 확인 화면에 반드시 표시한다.
- 일반 조회·자동 갱신은 저장·확정한 배정을 재계산하지 않는다. 예외적으로 규칙 변경에서는 8절의 영향 미리보기와 명시적 승인으로 미래 자동 배정을 변경할 수 있다.
- 확정 대상 전체가 적격이어야 저장한다. 일부 성공/일부 실패는 허용하지 않는다.
- CALENDAR_INTERVAL은 발생 건이 0개여도 담당 기간을 만들고 정해진 순환을 진행한다.
- EACH_OCCURRENCE는 생성 단계에서 휴일로 제외된 발생 건의 순번을 소비하지 않는다.
- 확정 후 발생 건을 취소해도 이미 공개한 순서는 되돌리지 않는다.
- 대타 변경은 특정 슬롯만 변경한다. 사유·변경 전후 직원·수정 시각·행위자를 기록한다.
- 과거/이미 시작한 발생 건의 일정 이동과 과거 담당 기간의 수정은 첫 단계에서 허용하지 않는다.
- 진행 중인 담당 기간의 남은 업무를 위한 대타는 허용한다. 이미 수행한 발생 건의 담당 스냅샷은 유지한다.
- 앞으로 두 사람의 차례를 교환하는 기능은 별도 후속 기능이다.

## 10. 상태·권한·후속 알림

목표 역할은 ADMIN과 MEMBER다. 관리자는 설정·확정·변경, 직원은 공개 일정·자기 담당 조회가 기본이다.
현재 로그인·권한은 구현 전이므로 UI 숨김만으로 권한을 보장했다고 간주하지 않는다.

메일·Pepper는 확정 배정과 실제 발생 건만 사용한다.
주간 안내는 금요일 퇴근 30분 전 다음 주 담당, 정례회 안내는 개최 주의 전 주 금요일 퇴근 30분 전이다.
휴무 금요일의 알림을 어느 날로 보낼지는 알림 단계에서 별도 결정한다. 현재 임의의 앞 근무일 이동을 확정하지 않는다.
정례회가 이동하면 실제 개최일 기준으로 안내 주를 재계산한다.

[운영 기간·담당 배정 범위 정책](allocation-window-policy.md): 명시적 생성 범위와 조회 시 저장 금지, 검토 후 기간 연장. 기존 자동 연속 생성 설명은 이 정책으로 대체한다.
