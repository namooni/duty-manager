# 참여자 제외 시 현재 담당 유지·인계 — 구현 정책

## 사용자 합의와 범위

주·월 담당의 현재 담당자를 참여 명단에서 제외할 때 이번 담당의 처리 방식을 선택한다. 일정 화면에서 현재 담당자를 변경하는 경우에도 같은 인계 검토를 사용하며, 이 경우 참여 명단은 유지한다. 기본은 「今回の担当が終わるまで継続する」이고, 필요하면 「残りの期間を別のメンバーに引き継ぐ」를 선택한다. 일반적인 담당 기간 날짜 편집이나 하루·이틀의 임시 대타 관리 기능은 추가하지 않는다.

참여 명단과 이미 배정된 담당은 구분한다. 승인 후 참여 명단은 즉시 새 명단이 되고, 제외된 사람이 현재 담당을 계속하는 경우 「今回のみ …まで担当」로 별도 표시한다. 실제 직원의 전사 유효·무효 상태와 당번 참여 여부는 별개다.

예: A·B의 차례가 지났고 수요일에 C가 담당 중이다. A·B·C를 제외하여 새 명단이 D·E·F가 되는 경우:

| 선택           | 어제까지 | 남은 기간  | 다음 자동 담당 |
| -------------- | -------- | ---------- | -------------- |
| 이번 담당 유지 | C 유지   | C 유지     | D              |
| D에게 인계     | C 유지   | 오늘부터 D | E              |

인계받은 사람은 이번 순환에서 담당한 것으로 반영한다. 랜덤은 남은 대기 순서에서 그 사람만 제외하고 다른 대기자의 순서를 유지한다. 직접 보호된 미래 담당은 기존 규칙대로 검토 화면에서 유지·해결하므로 자동 담당 후보와 다를 수 있다.

## 입력과 검토

참여자 편집에서는 현재 담당자를 새 명단에서 제외할 때 유지·인계 선택을 표시한다. 일정의 현재 담당자 변경에서는 명단 제외 없이 인계한다. 새 명단의 유효한 멤버에게 인계할 수 있다. 기본 후보는 기존 다음 차례 중 남아 있는 사람이다. 복수 담당은 중복되지 않는 인계자를 지정한다. 같은 기간을 계속 맡는 다른 담당자와도 중복할 수 없다.

인계는 서버의 Asia/Tokyo 날짜 기준 오늘부터 시작하며, 확정 직후 현재 담당에 반영한다. 오늘이 담당의 마지막 날이어도 오늘부터 인계할 수 있다. 대상외 기간에 해당하는 인계자는 차단한다. 인계 시 규칙 변경 시작은 다음 담당 경계로 고정하고, 인계자가 소비한 순서를 반영해 이후 자동 배정을 검토한다.

검토 화면에는 어제까지 보존되는 담당, 남은 기간의 인계, 다음 담당 변경을 함께 표시한다. 취소·입력 복귀·미리보기는 저장하지 않는다. 명단·순환 버전·미래 배정·인계·이력을 하나의 트랜잭션으로 적용한다. 동시 변경은 토큰으로 검증하고 재확인을 요구한다.

## 과거 보존과 후속 동작

기존 담당 슬롯과 날짜 경계는 유지하고, 인계 시작일부터 담당자만 별도 기록한다. 조회 시 같은 주도 ‘월~화 C / 수~일 D’처럼 담당 구간으로 나눈다. 이후 조회·규칙 변경·기간 연장으로 과거의 C가 D로 덮어써지지 않는다. 후일 D도 참여자에서 제외하면 그 시점의 현재 담당을 같은 절차로 다시 인계할 수 있다.

현재 진행 중인 담당의 변경은 공통 인계 검토를 통해 오늘부터 적용하고 다음 자동 순번을 조정한다. 과거에 끝난 구간은 이력 확인만 제공한다. 미래 구간의 단발 담당 변경은 기존 대타 정책대로 이후 자동 순번을 바꾸지 않으며, 요청의 from은 해당 구간의 시작일과 일치해야 한다.

예정된 인계자를 무효화하거나 새 명단에서 제거하는 경우에는 선행 인계 담당자 변경을 안내하고 적용을 막는다. 전사 멤버 무효화에서 현재 담당 처리까지 자동 확장하지 않는다. 원래 담당자는 인계가 실제로 시작된 뒤 현재 담당이 아니게 되면 기존 상태 변경 절차로 무효화할 수 있다.

기존 배정 범위를 넘는 담당 슬롯은 생성하지 않는다. 마지막 배정 기간에서 인계해도, 이후 기간을 추가할 때 인계받은 사람의 다음 차례부터 이어진다.

## 구현과 API

- CurrentHandoverService: 현재 실제 담당 조회, 명단 제외 대상·인계 적격성·영향 검토.
- AssignmentChangeService: 미래 순번 조정과 통합 승인 트랜잭션.
- SlotAssignmentResolver: 원래 슬롯과 날짜별 인계 기록에서 해당 날짜의 담당자·구간을 계산하는 공통 순수 함수. 조회·담당자 변경·현재 담당 판정에서 공유한다.
- HandoverRepository: 인계 기록과 기존 담당자 변경 이력을 저장한다. 서비스에 SQL을 두지 않는다.
- useAssignmentEditor: 선택 상태·후보·검증·요청 조립. UI는 훅 결과 표시와 이벤트 연결만 한다.

Flyway V7는 duty_slot_handovers와 duty_assignment_plans.members_from을 추가한다. members_from은 명단의 표시 적용일이며 담당 순서 계산의 시작 회차와 분리한다. 기존 migration과 과거 슬롯은 수정하지 않는다.

- GET /api/assignment-changes/duties/{id}: currentAssignments, nextCandidates, handoverDate 추가.
- preview/confirm input.handovers: {rotationSlotId: receiverEmployeeId}. 빈 객체는 이번 담당 유지다. 인계는 DUTY 변경에만 제공한다.
- 검토 응답 currentRows: 현재 유지·인계 구간. rows는 기존 미래 배정 변경이다.
- 일정 응답 segmented: 인계 이력이 있는 기간인지 나타낸다.
- 슬롯 담당 변경·후보 조회의 from: 변경하려는 오늘 또는 미래 구간의 시작일.

로컬 DB 검증은 임시 H2 MySQL 모드다. 실제 MySQL 검증과 구분한다.

이미 명단에서 제외했지만 이번 담당을 계속하는 사람도 재편집 시 인계를 선택할 수 있다. 같은 날 다시 인계하면 오늘의 담당을 최신 인계자로 갱신하고 변경 이력은 모두 보존한다. 오늘부터 시작한 구간에는 별도의 과거 보존 행을 만들지 않는다. 시간대별 대타 기록은 관리하지 않는다.

現在の週・月担当は、ホーム・予定一覧・詳細の「担当者を変更」からも共通の引継ぎ検討を使う。参加名簿は変えず、本日から担当し、引継ぎ先の次の自動担当を消費して後続を繰り上げる。手動指定は検討画面で保護・解消する。未来の単発変更は従来通り今回のみ。

同じ担当期間内に、参加除外した元の担当者を再追加すると、本日から元の担当へ戻す。名簿は元の担当者を引継ぎ先の前に戻し、引継ぎ先は次の自動担当へ戻す。検討画面で現在・今後の担当を確認して適用する。昨日までの記録と手動指定の保護は維持する。元の期間が終了した場合は現在担当を変更しない。
