# 担当ルール・メンバー状態変更の実装

## 対応範囲

担当詳細の「担当ルールを編集」から、参加者・順序・担当人数・適用開始回・先頭候補を変更する。メンバーの有効・無効も同じ変更前後の検討画面で確認してから適用する。プレビューとキャンセルでは保存しない。

過去・進行中の担当と開催日を維持し、今後の自動担当をまとめて更新する。手動指定は保護し、無効な担当者や重複は検討画面で代替者を指定する。競合する更新があれば再確認が必要。適用は状態変更・順序バージョン・担当枠・履歴を単一トランザクションで保存する。

無効化したメンバーは順序情報に保持し、実際の担当では飛ばして後続を詰める。有効化時は保持された順序に復帰する。経過した期間は巻き戻さない。明示的に参加者から除いたメンバーは、自動復帰の対象ではなく担当ルールで追加する。

固定順は次候補から継続する。社員番号順の状態変更では保存済み順序を維持する。ランダムは残りの順序を保持し、新規参加者を残りの後ろに追加する。以後の周回も保存シードで再現する。

## 安全上の制限

現在担当中のメンバーの無効化、旧形式の担当、後続に予約変更がある開始位置からのルール編集は、扱いの政策が未確定のため警告して適用しない。手動の追加担当枠を人数削減で消す場合も自動削除しない。実施日の繰り返し・交代期間の変更は今回の対象外。

## API・DB

- GET /api/assignment-changes/duties/{id}: 編集候補・適用開始回・履歴。
- POST /api/assignment-changes/preview: 変更前後・警告・競合解消候補・確認トークン。
- POST /api/assignment-changes/confirm: input と token を再検証して適用。
- GET /api/automatic-duties/slots/{id}/choices: 当該期間のバージョンに基づく代理候補。

Flyway V4 が担当ルールバージョンと名簿、状態変更と担当差分の監査履歴、計画ロックを追加する。担当枠は手動指定・退役を区別し、人数変更後も元の枠IDと履歴を保持する。計画関連処理は同じロックを先に取得し、並行処理による古い読取結果の適用を防ぐ。

UIは共通の useAssignmentReview と AssignmentReviewPanel を利用し、HTTP・変換・業務処理・表示を分離する。サーバーは AssignmentChangeService（変更手続き）、AssignmentProjectionService（版ごとの投影）、RotationAllocator（順番計算）、AssignmentPlanRepository（保存）に責務を分ける。

[운영 기간·담당 배정 범위 정책](allocation-window-policy.md): 명시적 생성 범위와 조회 시 저장 금지, 검토 후 기간 연장. 기존 자동 연속 생성 설명은 이 정책으로 대체한다.

## 現在担当の参加除外

当番の参加者から現在担当を除く場合は、今回のみ継続・承認直後、本日から引継ぎを選べる。社員の全社的な無効化とは別の手続き。[現在担当引継ぎ](current-assignment-handover.md)を現行仕様とする。
