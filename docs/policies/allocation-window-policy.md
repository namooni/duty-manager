# 운영 기간과 담당 배정 범위 — 구현 정책

사용자 합의: 당번 생성 시 운영 종료와 이번 담당 배정 범위를 별도로 설정한다. 5명 참여는 5회 종료를 의미하지 않는다. 지정한 기간 동안 순환 배정한다.

## 생성

- 開始日: 기존 anchorDate.
- 当番の終了: 終了日なし 또는 종료일(endDate). 운영 종료일은 시작일 이상이며 양 끝 포함이다.
- 担当者を決める期間: 시작일부터 plannedThrough까지. 화면의 기본 제안은 시작 연도의 연말이며 사용자가 바꿀 수 있다.
- 주·월 담당은 선택한 날짜가 속하는 기간 끝까지 배정한다. 실제 마지막 날짜를 서버 미리보기와 상세에 표시한다. 운영 종료일이 더 빠르면 그 날짜에서 마지막 담당 기간을 자른다.
- 회차별 담당은 지정 범위의 실시일만 배정한다. 개최일 개별 지정은 입력한 회차(미정 포함) 수만 배정한다. 참여자 수 때문에 미정 회차를 늘리지 않는다.
- 미리보기는 기간·회차 수·참여 인원·담당자를 보여준다. 뒤로 가기·취소는 저장하지 않는다. 확인 후 미리본 범위만 저장한다.

## 조회와 연장

일정·연간 상세 조회는 담당 슬롯을 추가하거나 수정하지 않는다. 배정 범위 이후에는 담당 일정이 없으며, 상세에서 배정 종료일과 「担当予定を追加」를 안내한다.

추가 범위를 선택하고 신규 담당 미리보기 후 확인한다. 이미 저장한 담당·수동 변경·슬롯 ID·변경 이력은 그대로 두고 누락된 다음 담당 슬롯만 추가한다. 다음 순번은 기존 규칙 버전과 순환 상태에서 이어진다. 개별 지정 정례회는 기간 연장과 함께 추가할 미정 회차 수를 선택할 수 있다. 날짜 등록만으로 새로운 회차를 자동 생성하지 않는다.

동시 변경은 토큰으로 검증하고 409 및 재확인을 제공한다. 추가와 범위 갱신은 하나의 트랜잭션이다. 운영 종료일 뒤로 연장할 수 없다. 현재 생성·연장은 한 번에 최대 3년/1,200담당, 개별 개최회차는 합계 200회까지다.

멤버 상태·규칙 변경 검토도 저장된 배정 범위 안의 미래 담당만 보여주고 갱신한다. 임의로 1년치 담당을 추가하지 않는다. 멤버의 상태 변경은 향후 연장 계산에도 적용되도록 순환 버전에 보존한다.

## 저장·API

Flyway V5는 duty_schedule_ranges(duty_id,end_date,planned_through)를 추가한다. 기존 당번은 저장된 담당 종료일·개최일·시작일 중 가장 늦은 날짜를 배정 범위로 이관한다. 이미 생긴 54건 등을 임의 삭제하거나 재배정하지 않는다. 기존 V1~V4는 수정하지 않는다.

- 생성 preview/activate의 draft: endDate(선택), plannedThrough(필수), dates(미정은 null).
- AutomaticDuty와 RotationPreview의 range: 서버가 계산한 실제 운영 종료/배정 종료.
- POST /api/automatic-duties/{id}/allocations/preview: plannedThrough, additionalMeetings.
- POST /api/automatic-duties/{id}/allocations: input, token.

ScheduleRange는 범위 판정과 마지막 기간 자르기를 공통화한다. ScheduleRangeRepository는 저장만, ScheduleAllocationService는 검토·승인·연장만 맡는다. 확인 토큰은 ConfirmationToken을 생성·규칙 변경·기간 연장에서 공유한다. 프론트 업무는 useAutomaticDutyCreation/useScheduleExtension, 미리보기 표시는 RotationPreviewList를 공유한다.
