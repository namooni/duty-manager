# 일정 상태 표시와 날짜 변경 — 구현 정책

## 날짜 기준 상태

Asia/Tokyo의 서버 기준일을 사용한다. 날짜 경과만으로 수행 완료를 추정하지 않는다. 실제 완료 체크는 이번 범위 밖이다.

| 상태    | 판정·표시                                                                                                         |
| ------- | ----------------------------------------------------------------------------------------------------------------- |
| 과거    | 담당 기간 종료/개최일이 오늘보다 이전. 「過去」, 중립 회색 배경·보조 글자색. 이름과 날짜는 읽을 수 있게 유지한다. |
| 진행 중 | 기간에 오늘이 포함되면 「担当中」과 강조선. 하루 일정이 오늘이면 「本日」.                                        |
| 미래    | 기본 표시.                                                                                                        |
| 미정    | 개최일 미정 표시를 유지하며 과거·진행 중으로 간주하지 않는다.                                                     |

조회 범위 일부만 보이더라도 주·월 담당의 상태는 전체 담당 기간으로 판정한다. 일정 목록과 연간 상세는 같은 순수 판정 함수와 스타일을 사용한다. 과거의 담당자 버튼은 「変更履歴」이며 입력 폼 없이 담당자·날짜 변경 이력을 읽는다.

## 미래 날짜 변경

### 하루짜리 일정

개별 지정·월간 자동 반복 등 OCCURRENCE 회차는 「開催日を変更」으로 해당 회차만 변경한다. 원래 담당자·슬롯 ID·회차 식별자·이후 순서는 유지한다. 시작일·배정 범위·운영 종료일 및 앞뒤 회차 순서를 지켜야 한다. 이미 날짜가 있는 오늘·과거 회차는 변경할 수 없다. 미정 회차의 최초 등록은 오늘부터 가능하다.

### 주·월 담당

주·월 담당(CALENDAR)의 시작일·종료일·교대일 변경은 제공하지 않는다. 「担当者を変更」으로 해당 기간의 담당자만 바꿀 수 있다. 하루·이틀 휴가의 자발적인 대행은 현장에서 조율하며 별도 일별 대타 기능은 구현하지 않는다.

기존에 변경된 기간과 날짜 변경 이력은 유지한다. UI의 기간 변경 버튼·제한 안내와 서버의 기간 날짜 변경 경로를 제거하며, 조회·규칙 변경·기간 연장은 저장된 날짜를 보존한다.

## 검토와 저장

개최일 변경 이유를 입력하고 해당 회차의 변경 전후 날짜를 확인한 뒤 적용한다. 취소·입력 복귀·미리보기는 저장하지 않는다. 대상외 기간에 해당하면 서버에서 차단하고, 회사 휴일로 옮기는 회차는 실행 없음 경고를 표시한다. 담당 인원·수동 대타·담당 이력은 유지한다.

동시 수정과 변경 후 원복(ABA)도 확인 토큰과 날짜 이력으로 감지해 409/재검토를 요구한다. 날짜 갱신과 날짜 변경 이력은 같은 트랜잭션이다. 날짜를 바꿔도 배정 범위를 늘리거나 조회로 담당을 추가하지 않는다.

## 구현 경계

- ScheduleTimelineService: 저장된 담당 슬롯의 날짜를 공통 시간축으로 반영한다. 조회·담당 순서 투영·현재 버전 판정·기간 연장에서 공유하므로 변경한 날짜가 이후 재계산으로 돌아가지 않는다.
- ScheduleDateChangeService: 변경 가능 범위·영향 검토·확인 토큰·승인. ScheduleDateRepository: 날짜 갱신과 이력 SQL. Controller는 전용 요청/응답 DTO만 전달한다.
- 클라이언트: useScheduleDateChange → scheduleDatesRepository → API. ScheduleDateChangeDialog는 결과 표시·입력 이벤트만 담당한다. schedulePhase는 순수 판정이며 UI는 훅 결과를 표시한다.

Flyway V6는 duty_schedule_date_changes를 추가한다. 날짜는 기존 duty_rotation_slots에 보관하고, 개별 지정 정례회의 duty_meetings 날짜도 함께 갱신한다. 이전 migration은 수정하지 않는다.

## API

- GET /api/automatic-duties/{id}/date-changes/{rotationKey}: 수정 가능 날짜 범위·현재 기간·이력.
- POST /api/automatic-duties/{id}/date-changes/preview: rotationKey, date, reason → 영향 목록과 token.
- POST /api/automatic-duties/{id}/date-changes: input, token → 204.
- GET /api/automatic-duties/{id}/date-changes/{rotationKey}/history: 과거 포함 날짜 이력.
- 기존 PUT /meetings/{sequence}는 미정 회차의 최초 날짜 등록에 사용한다. 이미 등록한 개최일 변경은 검토 API를 이용한다.

로컬 통합 검증은 H2 MySQL 모드다. 실제 MySQL 검증과 구분한다.
