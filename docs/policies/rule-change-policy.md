# 참가자·배정 규칙 변경 정책

기준일: 2026-10-27. 참가자·순서·인원·상태 변경은 구현했으며, 개최일 규칙 변경은 미구현이다. 상세 범위와 제한은 [구현 명세](assignment-change-implementation.md)를 따른다.

## 1. 이번 사용자 합의

1. **미래 배정은 변경 미리보기를 확인하고 명시적으로 승인하면 변경할 수 있다.** 이미 배정되었다는 이유만으로 적용일을 그 마지막 배정 이후로 미루지 않는다.
2. **새 규칙에서도 기존의 다음 차례부터 이어간다.** 그 사람이 새 참가자 명단에서 제외되면 기존 순서상 다음 남아 있는 사람부터 시작한다. 명단 첫 번째부터 일괄 재시작하지 않는다.

3. **신규 참가자는 배정 방식에 따라 편입하되 기존 다음 차례는 유지한다.** 사번순·지정순은 새 명단의 해당 위치에 편입하고, 랜덤은 기존 잔여 대기 순서 뒤에 신규 참가자를 추가한다.

4. **보호된 수동 배정과 새 규칙의 충돌은 변경 검토 화면에서 해결한다.** 건별 대체 담당자를 선택하고 규칙 변경과 함께 저장한다. 별도 일정 화면에서 먼저 수정하도록 요구하지 않는다.

기존 문서의 '마지막 확정 일정 이후에만 규칙 변경'과 '새 버전은 새 순환 시작'을 이 합의로 대체한다. 자동 조회·새로고침이 이미 공개된 배정을 몰래 바꾸어도 된다는 의미는 아니다.

## 2. 적용 시점과 보호 범위

- 과거 일정과 진행 중인 담당 기간을 규칙 변경으로 소급 재배정하지 않는다. 기간 담당은 기존 담당 기간 경계에서 새 규칙을 시작한다.
- 회차 담당은 아직 시작하지 않은 회차부터 변경한다. 참가자·배정 방식만 바꾸면 기존 개최일·회차 식별자는 유지한다.
- 적용 시점 이후의 자동 배정은 변경 미리보기 대상이다. 사용자가 승인하기 전에는 현재 운영 일정에 반영하지 않는다.
- 직접 담당자를 변경한 배정은 기본 보호 대상으로 분리해서 표시한다. 새 참가자·규칙과 충돌하면 사용자에게 해결을 요구하며 조용히 덮어쓰거나 없애지 않는다. 충돌 건의 대체 담당자는 같은 변경 검토 화면에서 선택하며, 규칙 변경과 함께 저장한다. 해결되지 않은 충돌을 자동 배정으로 덮어쓰는 방식은 제공하지 않는다.
- 개최일을 직접 지정한 정례회에서 참가자만 바꾼다고 개최일을 삭제하거나 정렬 순서를 다시 만들지 않는다. 실시일 규칙 자체를 바꾸는 경우의 날짜 보존·취소 범위는 별도 결정한다.
- 일정을 1년치 조회하여 배정이 저장되었더라도, 조회한 사실만으로 다음 변경 적용일이 1년 뒤로 밀리지 않는다. 조회 저장 여부와 사용자 승인·수동 보호 여부를 구분한다.

## 3. 다음 차례 이어가기

예: 기존 순서가 A → B → C → D → E이고 현재 B의 담당 기간이 진행 중이면, 다음 경계의 첫 후보는 C다. C가 새 명단에서 제외되면 D부터 시작한다. 버전이 바뀌었다는 이유로 A로 돌아가지 않는다.

- 다음 차례는 적용 경계 직전의 순환 상태를 기준으로 판단한다. 사용자가 과거에 어디까지 조회했는지에 따라 달라지지 않아야 한다.
- 기존의 대타 변경은 이후 순서를 바꾸지 않는 정책을 유지한다. 실제 대타 수행자만 보고 순환의 다음 후보를 역산하지 않는다.
- 미리보기·새로고침은 차례를 소비하지 않는다. 동일한 편집안의 결과는 다시 열어도 바뀌지 않아야 한다.
- 사번순·지정순은 다음 후보를 기준점으로 유지하면서 새 명단의 정렬·지정 순서를 따른다. 신규 참가자가 기준점 앞에 편입되면 기존 다음 후보보다 앞서 담당하지 않고 순환이 해당 위치에 돌아왔을 때 합류한다.
- 랜덤은 적용 경계의 현재 한 바퀴에서 아직 기다리는 기존 참가자 순서를 유지한다. 제외된 사람만 빼고 신규 참가자를 그 뒤에 추가한다. 신규가 여러 명이어도 미리보기·재조회로 서로의 순서가 다시 바뀌지 않아야 한다.
- 랜덤에서 말하는 '뒤'는 현재 한 바퀴의 잔여 대기열 뒤다. 연간 조회로 미리 저장된 모든 미래 배정의 마지막 뒤를 뜻하지 않는다. 그다음 순환은 변경된 전체 명단을 대상으로 기존의 전원 한 바퀴 랜덤 정책을 따른다.
- 배정 방식 자체 변경, 기존 참가자가 전부 제외되어 기존 기준점을 찾을 수 없는 경우의 첫 후보는 아직 미합의다.

### 신규 참가자 예시

- 사번순: 기존 사번 100 → 200 → 300에서 다음 차례가 200이면, 신규 150이 들어와도 200부터 시작한다. 새 순환 순서는 200 → 300 → 100 → 150 → 200이다.
- 사번순: 같은 조건에서 신규 250이 들어오면 200 → 250 → 300 → 100 → 200이다.
- 지정순: 신규를 편집 화면에서 선택한 위치에 편입하며, 기존 다음 후보를 기준으로 순환한다.
- 랜덤: 현재 잔여 순서가 C → D → E일 때 신규 F가 들어오면 C → D → E → F다. D가 제외되면 C → E → F다. 참가자 추가만으로 기존 대기자를 다시 추첨하지 않는다.

## 4. 변경 검토와 저장

권장 화면 흐름: 상세 → 규칙·참가자 편집 → 적용 시점 선택 → 변경 전후 비교 → 변경 적용.

검토 화면은 다음을 구분한다.

- 현재 규칙과 변경 규칙, 추가·제외되는 참가자, 적용 시작일 또는 회차.
- 첫 담당 후보와 기존 순환에서 이어지는 근거.
- 유지되는 배정, 담당자가 달라지는 배정, 보호된 수동 변경, 충돌하는 배정.
- 실시일 규칙까지 바뀌는 경우에는 추가·제외·이동되는 개최일도 구분한다. 이 항목의 구체 정책 확정 전에는 날짜 변경까지 묶어 구현하지 않는다.
- 화면의 선택 연도나 첫 페이지 밖에 영향 대상이 있다면 전체 영향 범위·건수를 명시한다. 일부만 보여주고 다른 미래 배정을 숨겨 변경하지 않는다.

변경 사유를 기록한다. 저장 시 대상 규칙·참가자·수동 변경·배정이 미리보기 이후 바뀌었으면 재검토를 요구한다. 새 규칙 버전과 승인된 배정 변경·이력은 함께 저장하며 일부만 적용하지 않는다. 이전 규칙과 변경 전 배정은 변경 이력으로 보존한다.

## 5. 추가로 결정할 정책

- 배정 방식 자체 변경과 기존 참가자 전원 제외: 기존 순환 기준을 이어갈 수 없을 때의 첫 후보 결정 방식.
- 배정 방식 자체 전환·전원 교체·실시일 변경과 퇴사·복귀의 세부 기준은 아래 미합의 항목을 구체화한다.
- 실시일·교대 규칙 변경: 기존 개최일과 회차·기간을 어떤 기준으로 연결하고 유지할지.
- 적용 대기 버전: 허용 개수와 재편집·취소 방식. 기존 목표 설계의 최대 1개는 아직 이번에 재합의한 항목이 아니다.

## 6. 구현 전 확인할 시나리오

| 상황                                 | 기대 동작                                                  |
| ------------------------------------ | ---------------------------------------------------------- |
| 연간 조회 후 다음 달부터 참가자 변경 | 조회한 마지막 배정일에 막히지 않고 전체 영향 미리보기 제공 |
| 진행 중인 주의 참가자 변경           | 그 주는 유지하고 다음 허용 경계부터 적용                   |
| 다음 후보가 새 명단에도 있음         | 그 후보부터 이어감                                         |
| 다음 후보가 새 명단에서 제외됨       | 기존 순서상 다음 남아 있는 후보부터 이어감                 |
| 직접 담당자를 바꾼 미래 배정 존재    | 보호 대상으로 표시하고 자동 덮어쓰기 금지                  |
| 참가자만 바꾸는 정례회               | 기존 개최일·회차 유지                                      |
| 미리보기 후 다른 사용자가 배정 수정  | 저장 차단·재검토, 부분 반영 없음                           |
| 미리보기를 취소하거나 반복 조회      | 운영 배정·순환 상태 변경 없음                              |

추가 검증: 사번순에서 신규자가 기준점 앞／뒤에 들어오는 경우를 각각 검증한다. 랜덤은 기존 잔여 순서 보존·제외자 제거·신규자 뒤편 편입을 검증하며, 연간 조회 여부로 합류 시점이 달라지지 않아야 한다.

## 7. 무효화 시 당김·유효화 시 원래 순서 복원 — 구현

### 현재 구현과의 구분

멤버 상태 변경은 영향 검토 후 미래 자동 배정을 함께 정리한다. 당번 참여·담당·변경 이력 등이 있는 멤버는 물리 삭제할 수 없다.

### 확인된 기본 동작

- 무효화하면 해당 멤버를 배정 대상에서 빼고 이후 사람들을 앞으로 당긴다. 담당자가 없는 주·회차·빈 배정 자리를 남기지 않는다. 개최일이나 담당 기간 자체를 건너뛰는 것도 아니다.
- 유효화하면 원래 순서의 위치에 멤버를 다시 포함시키고 영향받는 미래 배정을 다시 계산한다. 단순히 끝에 추가하거나 무조건 다음 한 바퀴까지 기다리게 하지 않는다.
- '원래 위치 보존'은 복원에 필요한 참가 순서·랜덤 위치·변경 전 정보를 보관한다는 뜻이다. 실제 일정에 빈 담당 자리를 예약한다는 뜻이 아니다.
- 기존과 같이 미래 배정 변경은 관련 당번 전체의 영향을 미리 보여주고 승인 후 반영한다. 무효화 때 앞당겨질 담당과 유효화 때 다시 뒤로 이동할 담당을 모두 명시한다.
- 유효화 시 원래 위치 복원은 기본 동작이다. 실수 정정을 위해 별도 취소 기능만 찾아야 하거나 다른 멤버를 삭제·재등록해야 하는 흐름으로 만들지 않는다. 변경 이력에서 취소하는 기능은 별도 편의 기능으로 검토할 수 있다.

### 예시: B가 담당 중이며 그사이 다른 변경은 없음

원래 순서 A → B → C → D → E → F …에서 D를 무효화했다가 다시 유효화하는 경우:

| 담당 기간 | 원래 | D 무효화 승인 후 | D 유효화 승인 후 |
| --------- | ---- | ---------------- | ---------------- |
| 현재      | B    | B                | B                |
| 다음      | C    | C                | C                |
| 그다음    | D    | E                | D                |
| 다음 기간 | E    | F                | E                |
| 다음 기간 | F    | G                | F                |

무효화 후에도 모든 미래 기간에는 담당자가 이어서 배정된다. 복원 시 D를 원래 순서에 넣고 이후를 다시 계산하므로, E 이후를 사람이 삭제·재등록할 필요가 없다.

### 보호 및 남은 결정

- 과거·이미 시작한 담당을 유효화로 되감지 않는다. 현재 담당 기간도 유지한다.
- 다른 수동 변경·참가자 수정이 있었다면 과거 전체 snapshot으로 덮어쓰지 않는다. 원래 순서를 참고하되 현재 상태와 충돌하는 미래 건을 검토 화면에서 해결한다. 수동 보호 충돌의 대체 담당자 선택은 규칙 변경과 함께 저장하는 합의를 따른다.
- 여러 번의 무효·유효 전환, 랜덤·복수 담당, 참가자 명단 자체 변경이 겹친 경우의 정확한 복원 기준은 후속으로 정한다.
- 무효화 대상이 현재 담당자인 경우와 대체 인원 부족으로 빈 기간을 채울 수 없는 경우, 담당이 진행된 뒤의 복귀 적용 경계·실패 처리는 추가 결정한다.

기존의 '무조건 다음 한 바퀴부터 복귀', '실수는 별도 무효화 취소로만 복원' 제안은 이 기본 동작으로 대체한다. 참가자·순서·인원·상태 변경은 검토 화면과 함께 구현했다.

## 현재 담당자 제외 시 명시적 인계

참여 명단은 승인 즉시 갱신하며, 현재 담당자는 이번 담당 완료 또는 확정 즉시 오늘부터 인계를 선택한다. 일반 규칙 변경의 진행 중 보호와 달리, 이 선택에 한해서만 남은 담당자를 바꾼다. 어제까지의 담당과 교대 경계는 유지한다. [현재 담당 인계 정책](current-assignment-handover.md)을 따른다.
