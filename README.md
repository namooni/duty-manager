# つぎばん / Duty Manager

社内の当番を、チームに合ったルールで管理するローカル開発版です。
Java 21 / Spring Boot / MySQL 8.4 / React / Vite / TypeScript / styled-components。

## 設計・ポリシー

次の実装に向けた [UI・サーバー・DBの設計文書](docs/README.md) を参照してください。
現在の実装は [実施日・自動担当順の構造](server/docs/architecture/automatic-duties.md) を参照してください。目標API・テーブルの全体が実装済みという意味ではありません。以下の実装済み機能とルールは現在のコードの説明です。

## 実装済み

- 社員番号・氏名の登録、有効・無効の切り替え
- 当番ごとの参加者、担当人数、開始日、N日・N週・Nか月の交代設定
- 社員番号順、選択した順、ランダム一巡の割当
- 対象外期間、人数不足の検出
- 実施日と交代ルールの分離、全員一巡のプレビュー、自動継続
- 確定済み担当者の変更、理由と変更履歴
- 日本語UI・エラーメッセージ、Asia/Tokyo基準の日付
- Flywayマイグレーション、テスト、GitHub Actions CI

## ローカル起動（PowerShell）

必要なもの：JDK 21、Node.js 24、Docker Compose。
既存のMySQLを使う場合はDockerの手順を省略し、専用DBを用意してください。

### 1. MySQL

プロジェクトのルートで以下を実行します。

```powershell
Copy-Item .env.example .env
# .env の2つのパスワードを変更する
docker compose up -d mysql
```

DockerのMySQLは localhost:3307 で待ち受けます。
既存の localhost:3306 のMySQLと分けています。
DB名は duty_manager、ユーザーは duty です。

### 2. サーバー

別のターミナルで以下を実行します。
DB_PASSWORDには .env に設定したものと同じ値を指定してください。
Spring Bootはルートの .env を自動では読み込みません。

```powershell
cd server
$env:DB_PASSWORD = 'your-local-password'
.\gradlew.bat bootRun
```

API：http://localhost:8080/api/health

既存MySQLを使用する場合：

```powershell
$env:DB_URL = 'jdbc:mysql://localhost:3306/duty_manager?connectionTimeZone=Asia/Tokyo'
$env:DB_USERNAME = 'your-dedicated-user'
$env:DB_PASSWORD = 'your-password'
.\gradlew.bat bootRun
```

### 3. フロントエンド

別のターミナルで以下を実行します。

```powershell
cd client
npm ci
npm run start:dev
```

画面：http://127.0.0.1:5173
開発時の /api は Vite が Javaサーバーへ転送します。

### 4. 使い方

1. メンバー画面で社員番号と名前を登録。
2. 「当番を作成」で業務と参加者、交代ルールを設定。
3. 全員一巡の担当順を確認し、「このルールで開始」。
4. スケジュール画面で実施日と担当者を確認。以降も自動で続きます。
5. 休暇などは対象外期間を追加。確定済みの場合は担当者を変更。

朝会の司会・議事録を週交代にする例：
実施日＝会社の勤務日、交代＝一定期間・1週、開始日＝月曜日、担当人数＝1人。
定例会の議事録は「開催日を個別に指定」「実施1回ごとに交代」を選びます。開催日は未定のまま開始し、後から登録・変更できます。
ゴミ出しは別の当番として同じ手順で登録します。

通常のDB統合テストはH2のMySQLモードを使用します。

## ルールの仕様

- 実施日と交代周期は別です。会社休業日は実施なしになり、交代日は変わりません。会社の勤務日は現在、月〜金です。
- 指定順は参加者を選択した順番。社員番号順は文字列順なので桁数をそろえてください。
- 月単位は元の開始日を基準に計算。1/31 → 2/28 → 3/31。
- ランダムは再表示しても同じ結果になります。対象外なし・担当1人なら全員が一巡してから次の順番になります。
- 複数人の割当では同じ期間の重複を避けます。休暇や有効状態によって実際の回数は偏る場合があります。
- 対象外期間が担当期間に1日でも重なると、その期間全体をスキップ。後日の優先補填はありません。
- 新規当番は終了日を指定せず自動的に続きます。表示期間は閲覧用です。
- プレビュー後に内容が変わった場合は確定を拒否し、再確認を求めます。
- 確定済みの割当は自動では変更しません。代理の変更はその枠だけに適用し、元の順番は入れ替えません。
- 表示範囲は最大367日、開始日からの計算は最大4,000期間。
- 現段階は新規作成中心です。作成後のルール・参加者編集、対象外期間の編集・削除、当番の停止は今後の対応です。

既存の形式で保存した担当期間・履歴は保持します。実際の開催日を推測した自動移行は行いません。
サーバー変更後は再起動してください。FlywayがV3の追加テーブルを作成します。

## 今後の拡張

- ルールの適用開始日とバージョン管理、参加者の変更
- 当番交換、業務間の重複回避、負担の集計
- 社内ログインと管理者権限
- メール、Pepper通知、AWSへのデプロイ

通知は将来、確定した担当と実際の開催日を参照します。
週当番：金曜の終業30分前に翌週分。
定例会：開催週の前週金曜、終業30分前。
終業時刻は会社設定として持たせ、現時点では固定しません。

現在はログイン未実装のローカル開発版です。社内公開は認証・権限の実装後に行います。
AWSリソースの作成、GitHubへのpush、デプロイは実行していません。
